## W1（10/09–10/18）

- [1] 两数之和：不要双重循环。用 HashMap 存「值 → 下标」，遍历时先查 `target-nums[i]` 再存自己，O(n)。
      关键洞察：把「找配对」变成「查表」——因为到了下标 i，要配的那个数是**确定能算出来的**。
- [26] 删除有序数组中的重复项：快指针探路、慢指针写。有序保证重复相邻，所以只跟 `nums[slow-1]` 比就能判断新值。
      关键洞察：「原地删除」= 把有效数据往前搬 + 返回新长度（数组长度根本没变，后面是垃圾）。
- [27] 移除元素：和 26 同一套骨架，两处不同——`slow` 从 0 开始（第一个元素也可能删）、比较对象是常量 `val`（不依赖有序）。
      关键洞察：和谁比，决定了这个套路能解什么问题（跟上一个保留值比 → 去重；跟常量比 → 过滤）。

## 套路模板

### 双指针 · 快慢（原地删除类）

适用：**原地**删除 / 去重 / 压缩，要求 O(1) 额外空间。

```text
slow = 起点的下一个位置（或 0，看第一个元素是否必然保留）
for fast in [起点, n):
    if 当前元素应该保留:
        nums[slow] = nums[fast]
        slow++
return slow        ← slow 同时是"下一个待写位置"和"已保留个数"
```

| 题 | slow 初值 | 比较对象 | 依赖有序 |
|---|---|---|---|
| 26 删除重复项 | 1 | `nums[slow-1]` | ✅ |
| 27 移除元素 | 0 | `val`（常量） | ❌ |

### 哈希表 · 空间换时间

适用：**查"某个值出现过吗 / 在哪个位置"**。

```text
Map<K, V> map = new HashMap<>();
for (每个元素 e) {
    K need = 由 e 推出的"我要找的东西"
    if (map 里有 need) return 答案
    map.put(e 的键, e 的值)      ← 顺序不能反：先查后存
}
```

**顺序为什么不能反**：`[3,3], target=6` 这组用例——如果先存后查，第一次循环就把 `3→0` 存进去了，第二次查到的是**同一个元素**，返回 `[0,0]`，而题目要求同一元素不能复用。
